Count people at the edge, merge them, keep the proof

Cameras produce far more video than anyone can watch. This example keeps the watching at the edge. A detector counts people in each camera, a fusion node merges the counts, and only the events that matter move on, signed and archived.

What it does

  • Detection stays local. YOLO runs on the node. Nothing leaves it for the node to know what it is looking at.
  • The merge happens at the edge. The fusion node adds the per-zone people counts into one combined count, on the same node, with no round trip to a control room.
  • An analyst summary is optional. When a detection warrants it the sensor asks the demo model gateway for one sentence. Rehearsals replay recorded answers; no model is called.
  • The mission updates live. Arm a new class once and every sensor picks it up within about a second, with no restart.
  • The link can drop. Sensors keep detecting and the dashboard keeps painting. Events queue on disk and the archive drains when the link returns.

The merge rule

The crowd flag trips when the combined count across the cameras is at least 3 (EDGE_CROWD_THRESHOLD), every camera sees at least one person, and the busiest sees at least two. It fires once per crossing and then waits for the count to drop.

Flag. North 2 and south 1 make 3, both zones occupied, one with two.

No flag. North 4 and south 0 make 4, but the crowd is in one camera only.

Two examples on one engine

The Edge ISR cascade is the headline: five pipelines. Box counting is the original warehouse demo: four pipelines. Both run as Expanso Edge jobs from jobs/, and the explorer below walks through every one of them.

Where the sample data comes from

Every record in the explorer is real output, never typed in. The stage inputs and outputs were produced by Expanso Edge v2.1.21 on 2026-10-05.

  • fixtures/scenes/north.jsonl: YOLO yolov8s detections measured on a viewing window panned down the Ultralytics sample photograph bus.jpg (41 frames).
  • fixtures/scenes/south.jsonl: The same weights on a window panned across zidane.jpg (41 frames).
  • fixtures/capture/: The output of the real producers on those scenes: edge-sensor, edge-orchestrator and the fuse correlator, with the analyst answers replayed from fixtures/model/.
  • recordings (not committed): Two cameras filmed for two minutes while boxes were carried through a door. esc-infer, detect_loop.py and esc-record ran on that footage with the yolov8s-worldv2 weights; their output is in fixtures/capture/.

Run it

  1. Install

    Python 3.11 or newer and uv. No GPU, camera or model weights are needed to replay the recorded scenes.

    uv sync

  2. Start the fusion node

    The dashboard and this guide are served from it.

    uv run edge-orchestrator --port 8080

  3. Replay both recorded scenes

    Each command plays 41 frames of real detections through the sensor's trigger, threshold, analyst, signing and emit path. Run them in two terminals.

    uv run edge-sensor --replay fixtures/scenes/north.jsonl \
  --node-id sensor-north --orchestrator http://localhost:8080 \
  --speed 2
    uv run edge-sensor --replay fixtures/scenes/south.jsonl \
  --node-id sensor-south --orchestrator http://localhost:8080 \
  --speed 2

  4. Watch the merge

    Open the dashboard. The flag trips when the combined count reaches 3 with at least one person in each zone and two in the busier one.

  5. Run a pipeline on its fixture

    This deploys the real job to a throwaway Expanso Edge container with its input and output swapped for files, the same method the proof uses. It needs Docker.

    uv run -s scripts/edge-replay.py jobs/fuse-job.yaml \
  fixtures/fuse/input.jsonl

  6. Rebuild every fixture and this page

    uv run -s scripts/build-fixtures.py
uv run -s scripts/build-guide.py

  7. Live cameras

    Two USB webcams on a laptop, no Expanso job.

    uv run --extra vision edge-sensor --cameras 0,1 \
  --orchestrator http://localhost:8080

Deploy it

  1. Prepare the node

    Install Expanso Edge and bootstrap it into your cluster. Label it so the jobs find it, put this repository on it, and give it the YOLO weights.

    sudo mkdir -p /opt/edge-isr/state /opt/edge-isr/archive /opt/edge-isr/models
git clone https://github.com/aronchick/expanso-edge-video-and-event-detection \
  /opt/edge-isr/app
cd /opt/edge-isr/app && uv sync --extra vision

    Node settings, read by the jobs from the agent's environment:

    • EDGE_ISR_HOME default /opt/edge-isr/appThis repository.
    • EDGE_ISR_STATE default /opt/edge-isr/stateDatabases, the event log, audit files.
    • EDGE_ISR_ARCHIVE default /opt/edge-isr/archiveDaily archive files.
    • EDGE_ISR_ORCHESTRATOR default http://localhost:8080Where sensors send events.
    • EDGE_ISR_NORTH_SOURCE, EDGE_ISR_SOUTH_SOURCE default local go2rtc RTSPCamera RTSP URL or webcam index.
    • EDGE_ISR_YOLO_MODEL default /opt/edge-isr/models/yolov8s.ptYOLO weights or a TensorRT engine.
    • EDGE_CROWD_THRESHOLD default 3Combined people needed to flag.
    • EDGE_ISR_BIND default 127.0.0.1Fusion node listen address. The API has no login; use 0.0.0.0 only on an isolated LAN.

  2. Deploy the jobs

    Fusion node first, then the sensors, the fuse pipeline and the archive.

    for job in orchestrator sensor-north sensor-south fuse event-archive; do
  expanso-cli job deploy jobs/$job-job.yaml
done
expanso-cli job list

    Each job's page in Expanso Cloud now shows real logs (one line per event or alert) and real input and output rates.

  3. Give the archive somewhere to write

    The archive job writes to S3 with the standard AWS credential chain over HTTPS (S3 encrypts the objects at rest by default), and needs only permission to put objects under events/.

    {
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": "s3:PutObject",
    "Resource": "arn:aws:s3:::edge-isr-events/events/*"
  }]
}

    The policy above is for a bucket named edge-isr-events; use your bucket's name. Set EDGE_ISR_S3_BUCKET and AWS_REGION in the agent's environment. For a private S3-compatible endpoint also set EDGE_ISR_S3_ENDPOINT and AWS_CA_BUNDLE. When the WAN drops the sensors and the dashboard keep running and Expanso Edge buffers the archive writes until the link returns.

  4. Jetson

    Export the TensorRT engine on the device, set up its camera LAN, and install the nightly updater.

    python scripts/export_tensorrt.py
sudo scripts/setup_jetson_lan.sh
scripts/install_jetson_update_timer.sh --enable

  5. Box counting

    The GPU detector runs in the pinned Ultralytics Jetson image with the NVIDIA runtime. Put .env with the camera credentials and the weights in BOX_DATA_DIR.

    for job in yolo-detector security-camera-events box-crossing recorder; do
  expanso-cli job deploy jobs/$job-job.yaml
done
